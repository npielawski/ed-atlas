# ED Atlas: reproducing the models and figures

Code for the paper on an atlas of 30-day mortality and diagnosis probabilities for emergency department (ED) patients, given age, sex and presenting complaint (SNOMED CT). The companion website is ed-atlas.org.

Two families of Bayesian logistic regressions (`sex * spline(age) * symptoms`, fitted with PyMC and the numpyro sampler) are trained on the Swedish SwED cohort:

- one **mortality** model, and a **base** model without symptoms used for relative risk;
- one **diagnosis** model per ICD-10 code (930 models: chapters, blocks and three-character codes).

They are tested on SwED itself, on Uppsala (AKKIS) and on MIMIC-IV.

This document is a recipe. Follow it from top to bottom.

## 1. Requirements

- Python 3.11 with `polars`, `fastexcel`, `pymc`, `numpyro`, `jax`, `arviz`, `patsy`, `xarray`, `numpy`, `scipy`, `scikit-learn`, `matplotlib`, `pandas`, `geopandas`, `tqdm`, `netcdf4`.
  The paper's models and scores were produced with polars 1.9.0, PyMC 5.17.0, numpyro 0.15.3, ArviZ 0.20.0, JAX 0.4.31, pandas 2.2.3 and numba 0.60.0. The scripts also ran with polars 1.40.1 and PyMC 5.28. Use `polars<2`: version 2.0 changed `read_csv(columns=..., new_columns=...)`.
- [Miller](https://miller.readthedocs.io) (`mlr`) and `gunzip`, for step 2c only.
- Training the 930 diagnosis models is compute heavy (a GPU and a cluster make it practical). The mortality model and every plot run on a laptop.

The scripts read and write relative paths, so run everything **from the root of this repository**.

## 2. Data

### 2.0 Folder layout

Create this layout in the repository root (the data folders are git-ignored, except `data/maps/`). Each folder under `data/` can be a symlink to wherever the real data is stored.

```
.
├── *.py, triage2snomed.sh   the scripts
├── data/                    raw input data (never modified)
│   ├── swed/                SwED + national registers  (section 2.1)
│   ├── uppsala/             Uppsala AKKIS              (section 2.2)
│   ├── mimic/               MIMIC-IV and MIMIC-IV-ED   (section 2.3)
│   └── maps/                public map data            (section 2.4)
├── mappings/                code lists and term files  (section 2.5)
├── datasets/                generated by the generate_dataset_*.py scripts
├── models/
│   ├── columns/             column order of every fitted model
│   └── diagnoses/           per-age probabilities, written by plot_diag_pymc.py
├── figures/
│   ├── test/
│   ├── risks_en/  risks_svg_en/
│   └── diags_{chapters,blocks,codes}_en/  diags_{chapters,blocks,codes}_svg_en/
└── web_data/                JSON files of the website
```

```bash
mkdir -p data/{uppsala,mimic,maps} mappings datasets models/{columns,diagnoses} \
  figures/{test,risks_en,risks_svg_en} web_data
for l in chapters blocks codes; do mkdir -p figures/diags_${l}_en figures/diags_${l}_svg_en; done
```

### 2.1 SwED (`data/swed/`)

Access-controlled: obtained through the SwED research programme, which links ED visits to the National Patient Register and the Cause of Death Register (Socialstyrelsen). The data never leaves its secure environment, so `data/swed` can be a symlink to the folder that holds the parquet files, for example:

```bash
ln -s /proj/nobackup/sens2020598/swed_db/clean_parquet data/swed    # our project on Bianca
```

## 3. Reproduction

### Step 1. Datasets

SwED (run twice, see below):

```bash
python generate_dataset.py            # with prune_diag = True  (top of the script)
# set prune_diag = False, then
python generate_dataset.py
```

Writes `datasets/mortality*.parquet`, `datasets/mortality_unique.parquet` and the diagnosis datasets. The pruned run (leaves with fewer than 100 observations merged into their parent) writes the `*_pruned.parquet` files that define which diagnoses are modelled; the unpruned run writes the data the models are trained and tested on.

Uppsala and MIMIC-IV:

```bash
python generate_dataset_akkis.py                # datasets/akkis_*.parquet
./triage2snomed.sh                              # datasets/mimic_symptoms.txt
python generate_dataset_mimic.py                # datasets/mimic_*.parquet
```

### Step 2. Mortality models

```bash
python train_mort.py       # base_model = False  ->  models/trace.nc
# set base_model = True at the top of train_mort.py, then
python train_mort.py       #                     ->  models/trace_base.nc
```

Also writes `models/columns/columns_mortality.csv`.

### Step 3. Diagnosis models

`train_diag.py` fits one diagnosis per run. The argument is the position of the diagnosis in the sorted list of modelled codes, so run it once for every value from 0 to 929:

```bash
for i in $(seq 0 929); do python train_diag.py $i; done
```

Writes `models/trace_diag_<code>.nc` and `models/columns/columns_<code>.csv`. Existing traces are skipped.

### Step 4. Tests

Each script loads the figure saved by the previous one and adds its dataset to it, so run them in this order.

Mortality:

```bash
python test_mort.py            # SwED
python test_akkis_mort.py      # Uppsala
python test_mimic_mort.py      # MIMIC-IV
```

Diagnoses, once for each ICD chapter `N` in 01–17, 19, 20:

```bash
python test_diag.py N
python test_akkis_diag.py N
python test_mimic_diag.py N
```

The scores are printed, and the four-panel curves (ROC, precision-recall, calibration) are saved in `figures/test/`.

To run all of them (mortality, then the 19 chapters, on the three datasets, in the right order) and collect the scores in `models/metrics_diagnoses.csv`, the table that step 5 reads:

```bash
python collect_metrics.py                  # all posterior draws
python collect_metrics.py --draws 200      # quick check
```

Finished (dataset, diagnosis) pairs are skipped, so the script can be restarted.

### Step 5. Figures and web data

```bash
python plot_risk_pymc.py                          # Fig. 3, and models/static_*mort_predictor.csv
python plot_diag_pymc.py chapters SYMPTOM_INDEX   # Fig. 4 (also: blocks, codes)
python plot_results_figure.py                     # Fig. 5
python plot_communes.py                           # appendix map
python generate_web_data.py                       # web_data/*.json
```

- `plot_risk_pymc.py` plots every symptom; Fig. 3 is `figures/risks_en/risk_21522001.pdf` (abdominal pain).
- `plot_diag_pymc.py`: set `symptom_to_plot = "21522001"` in the script to plot abdominal pain (Fig. 4), or pass the symptom index as the second argument. It also writes the per-age JSON files in `models/diagnoses/`.
- `plot_results_figure.py` reads `models/metrics_diagnoses.csv`, written by `collect_metrics.py` in step 4, with the columns `dataset` (`SwED`, `Akkis`, `MIMIC`), `diagnosis` (chapter number), `metric`, `score`, `ci_low`, `ci_high`.
- `generate_web_data.py` needs `plot_risk_pymc.py` to have run first. It adds differentially private noise to the survivor counts (discrete Laplace, ε = 2), so its output changes at every run by design.

### Step 6. Fig. 2: scatter plots of symptoms and diagnoses

Fig. 2 is not drawn by a Python script. The scatter plots are the "symptoms" and "diagnoses" pages of the companion website, [ed-atlas.org](https://ed-atlas.org), and the figure was exported by hand from those pages (as SVG, with the dead-on-arrival symptom removed). The pages are drawn from two JSON files, which this repository generates:

```bash
python generate_web_data.py        # writes web_data/symptoms.json and web_data/diagnoses.json (and more)
```

Run it after step 1. For these two files it only needs `datasets/mortality.parquet` and `datasets/mortality_unique.parquet`, written by the SwED dataset script, and the mappings. The script also writes the website's other data files, which need the outputs of steps 2 and 5; the two scatter-plot files are written first. The website reads them from `src/data/`.

| File | One entry per | Fields |
|---|---|---|
| `symptoms.json` | presenting complaint (SNOMED CT) | `id`, `term`, `n_pop` (ED visits), `deaths` (deaths within 30 days) |
| `diagnoses.json` | ICD-10 code at every level of the hierarchy, and `NODIAG` | `id`, `term`, `n_pop`, `n_dead`, `mu` (30-day mortality given the diagnosis) |

How the website turns them into points:

- **x axis:** `n_pop` per 100,000 ED visits, using the total of 7,801,241 ED visits (a constant in the website's code).
- **y axis, diagnoses:** `mu`, the posterior mean of a hierarchical Beta-binomial model in which the prior of each diagnosis depends on its ICD-10 ancestors.
- **y axis, symptoms:** the posterior mean of a Beta-binomial model with a single shared prior. Its mean and sample size are printed by `generate_web_data.py` (`mu` and `ns`). The website uses 0.035 and 10.7 for symptoms, and 0.037 and 9.5 for diagnoses, as the defaults of its prior sliders.
- **Privacy:** survivor counts of the diagnoses are made differentially private in `generate_web_data.py` (discrete Laplace noise, epsilon = 2, taking the depth of the ICD-10 tree into account, followed by a consistency step across the hierarchy). The noise comes from a cryptographically secure generator and is not seedable, so every run gives slightly different diagnosis positions. The figure in the paper corresponds to one draw, which is why the caption calls the diagnosis positions approximate.

## 4. Which script makes what

| Paper | Script |
|---|---|
| Fig. 2 | data: `generate_web_data.py`; the plots: the scatter pages of [ed-atlas.org](https://ed-atlas.org) (step 6) |
| Fig. 3 | `plot_risk_pymc.py` |
| Fig. 4 | `plot_diag_pymc.py` |
| Fig. 5 | `collect_metrics.py` (scores), `plot_results_figure.py` |
| Appendix: municipality map | `plot_communes.py` |
| Appendix: ROC, precision-recall and calibration curves | `test_*.py` (`figures/test/`) |
| Models | `train_mort.py`, `train_diag.py` |
| Datasets | `generate_dataset*.py`, `triage2snomed.sh` |

Helper modules: `icd.py`, `snomed.py` (term mappings), `quantiles.py`, `calibration_curve.py`, `test_toolkit.py` (scores and test plot), `colorscheme.py`.

The age spline knots are fixed at `[22, 43, 65, 88]` (the weighted 5/35/65/95th percentiles of age in SwED). They appear in the training, test and plotting scripts and must be changed together.
